### Deployment Model

Single-server deployment. FastAPI serves the SvelteKit static build from `/build` (or `dist`) via `StaticFiles` middleware. This eliminates CORS complexity and simplifies the PWA scope to a single origin.

```python
# main.py
from fastapi import FastAPI
from fastapi.staticfiles import StaticFiles

app = FastAPI()
app.mount("/", StaticFiles(directory="frontend/build", html=True), name="static")
```

PWA manifest and service worker are generated by SvelteKit at build time.

### Core Scan Workflow (Request/Response)

```
User scans QR sector
  |
  v
Scanner.svelte -> POST /api/auth/me (validate session)
  |
  v
Scanner.svelte -> GET /api/sectores/lookup?qr_valor=A-F1-C2
  |
  v
Backend: SELECT * FROM ubicaciones WHERE qr_valor = ?
  |
  v
UI: Location anchored (scannerStore.anchoredLocation = ubicacion)
  |
User scans product barcode
  |
  v
Scanner.svelte -> GET /api/productos/7501234567890
  |
  v
Backend: SELECT * FROM productos WHERE codigo_de_barra = ?
  |
  v
UI: ProductCard shows sku, desc, accumulated stock
  |
User enters quantity, taps Guardar
  |
  v
Scanner.svelte -> POST /api/movimientos
  |
  v
Backend (transaction):
  1. SELECT stock_actual FROM ubicaciones WHERE id = ?
  2. INSERT INTO movimientos (...)
  3. UPDATE ubicaciones SET stock_actual = ? WHERE id = ?
  4. Commit
  |
  v
UI: Success toast, ready for next product scan
```

### Seed Data Strategy

On first startup, if `usuarios` is empty, the backend inserts a default admin user (or leaves it to the first login). The login endpoint auto-creates a `usuarios` row if the name does not exist, eliminating a separate user-management screen for MVP.

```sql
-- Optional seed (run once on migration v1)
INSERT INTO usuarios (nombre) VALUES ('Admin'), ('Operario 1'), ('Operario 2')
ON CONFLICT DO NOTHING;
```

## 3. API Endpoint Design

### Error Response Format (consistent)

```json
{
  "error": "Descriptive error message",
  "code": "ERROR_CODE",
  "detail": null
}
```

### SQLITE_BUSY Retry Middleware

Applied as a FastAPI dependency wrapper around repository calls that perform writes. Catches `sqlite3.OperationalError` with code `SQLITE_BUSY`, retries with exponential backoff (50 ms, 100 ms, 200 ms), then returns HTTP 503 if exhausted.

### Endpoint Table

#### Auth

| Method | Path | Auth | Request Body | Response Body | Description |
|--------|------|------|--------------|---------------|-------------|
| POST | `/api/auth/login` | No | `LoginRequest` | `UserSession` | Create user (if new) + session |
| POST | `/api/auth/logout` | Yes | -- | `{"ok": true}` | Invalidate session |
| GET | `/api/auth/me` | Yes | -- | `UserSession` | Return current session |

#### Excel Import

| Method | Path | Auth | Request Body | Response Body | Description |
|--------|------|------|--------------|---------------|-------------|
| POST | `/api/import/excel` | Yes | `multipart/form-data` (file) | `ExcelImportResponse` | Parse xlsx, validate, import |

#### Products

## 5. Scanner Component Design

### Lifecycle Mapping (Svelte <-> html5-qrcode)

```typescript
// src/lib/components/Scanner.svelte
<script>
  import { onMount, onDestroy } from 'svelte';
  import { browser } from '$app/environment';
  import {
    Html5QrcodeScanner,
    Html5QrcodeScanType,
    Html5QrcodeSupportedFormats,
    Html5QrcodeScannerState,
  } from 'html5-qrcode';

  let scanner: Html5QrcodeScanner | null = null;
  let readerEl: HTMLDivElement;

  onMount(() => {
    if (!browser) return;

    scanner = new Html5QrcodeScanner(
      'reader',
      {
        fps: 10,
        qrbox: { width: 250, height: 250 },
        aspectRatio: 1.777778,
        rememberLastUsedCamera: true,
        supportedScanTypes: [
          Html5QrcodeScanType.SCAN_TYPE_CAMERA,
          Html5QrcodeScanType.SCAN_TYPE_FILE,
        ],
        formatsToSupport: [
          Html5QrcodeSupportedFormats.QR_CODE,
          Html5QrcodeSupportedFormats.EAN_13,
          Html5QrcodeSupportedFormats.CODE_128,
          Html5QrcodeSupportedFormats.UPC_A,
        ],
        showTorchButtonIfSupported: true,
        showZoomSliderIfSupported: true,
        useBarCodeDetectorIfSupported: true,
      },
      /* verbose= */ false
    );

    scanner.render(onScanSuccess, onScanFailure);
  });

  onDestroy(() => {
    if (!scanner) return;
    const state = scanner.getState();
    if (state === Html5QrcodeScannerState.SCANNING) {
      scanner.pause(true); // freeze video before stop
    }
    scanner.clear().catch(() => {});
    scanner = null;
  });
</script>

<div id="reader" bind:this={readerEl}></div>
```

### State Machine

```
IDLE
  |
  v (onMount completes, camera starts)
SCANNING_SECTOR
  |
  +-- QR_CODE scanned ---> LOCATION_ANCHORED
  |
  +-- barcode scanned ---> show warning "Escanee primero el QR del sector"

LOCATION_ANCHORED
  |
  +-- QR_CODE scanned ---> re-anchor to new location
  |
  +-- barcode scanned ---> SCANNING_PRODUCTS

SCANNING_PRODUCTS
  |
  +-- product found ---> show ProductCard + StockInput
  |
  +-- product not found ---> show "Producto no encontrado"
  |
  +-- barcode debounced ---> ignore

SAVING_STOCK
  |
  +-- success ---> back to SCANNING_PRODUCTS (location still anchored)
  |
  +-- 503 SQLITE_BUSY ---> show retry button
  |
  +-- error ---> show error toast
```

### Format Detection Branch

```typescript
async function onScanSuccess(decodedText: string, result: any) {
  const format = result.result.format?.formatName as string;
  const now = Date.now();
  const state = get(scannerStore);

  // Debounce: ignore same code within 2 seconds
  if (decodedText === state.lastScanCode && (now - state.lastScanTime) < 2000) {
    return;
  }
  scannerStore.update(s => ({ ...s, lastScanCode: decodedText, lastScanTime: now }));

  if (format === 'QR_CODE') {
    // Sector lookup
    const loc = await api.get(`/api/sectores/lookup?qr_valor=${encodeURIComponent(decodedText)}`);
    if (loc) {
      scannerStore.update(s => ({ ...s, anchoredLocation: loc }));
    } else {
      toast.error('Ubicacion no registrada');
    }
  } else {
    // Barcode (EAN_13, CODE_128, UPC_A)
    if (!state.anchoredLocation) {
      toast.warning('Escanee primero el QR del sector');
      return;
    }
    const product = await api.get(`/api/productos/${encodeURIComponent(decodedText)}`);
    if (product) {
      scannerStore.update(s => ({ ...s, lastProduct: product }));
    } else {
      toast.error('Producto no encontrado');
    }
  }
}
```

### Pause/Resume for Batch Workflow

After a successful product scan, the scanner remains active (`SCANNING_PRODUCTS` state). The user enters quantity and taps Guardar. The scanner is NOT stopped during data entry -- it continues scanning in the background, but debounce prevents duplicate triggers. If the user needs to focus on typing, the UI may overlay a semi-transparent panel that does NOT pause the scanner (to keep the workflow fast), but pausing is available via `scanner.pause(true)` if needed.

### Cell Sizing & Touch Targets

- Minimum cell size: `minmax(48px, 1fr)` -- guarantees 48x48px touch target on all devices.
- Gap: `4px` for visual separation without wasting space.
- On very small screens (< 375px), allow horizontal scroll per shelf instead of squishing cells below 48px.

### Color Coding

Driven by `ubicacion` state, applied via CSS classes:

```typescript
function cellClass(u: UbicacionOut): string {
  if (u.id === selectedCellId) return 'cell-selected';   // blue #3b82f6
  if (!u.producto_id) return 'cell-empty';               // gray #9ca3af
  if (u.stock_actual <= 5) return 'cell-low';            // yellow #eab308
  return 'cell-ok';                                      // green #22c55e
}
```

### Touch Interaction

1. **Tap** -> `selectedCellId` updates -> cell gets blue border.
2. **Detail panel opens** below the tapped shelf (not a modal -- avoids covering the grid).
3. **Confirm button** inside the panel triggers the assignment/relocation API call.
4. **No action on tap alone** -- prevents accidental mutations.

### Landscape vs Portrait

- **Scanner route (`/scanner`)**: Optimized for portrait (phone held vertically, camera viewfinder is tall).
- **Map route (`/mapa`)**: Works in both; landscape gives more horizontal space for wide shelves. CSS Grid auto-fills horizontally; no orientation lock required.

```
User A          User B          FastAPI A           FastAPI B           SQLite (WAL)
 |               |               |                   |                   |
 | save qty 5    |               |                   |                   |
 |-------------->|               |                   |                   |
 |               |               |--BEGIN------------>|                   |
 |               |               |--SELECT stock=10-->|                   |
 |               |               |                   |                   |
 |               | save qty 3    |                   |                   |
 |               |-------------->|                   |                   |
 |               |               |                   |--BEGIN----------->|
 |               |               |                   |--SELECT stock=10->|
 |               |               |                   |                   |
 |               |               |--INSERT mov (10->15)                   |
 |               |               |--UPDATE stock=15-->|                   |
 |               |               |--COMMIT----------->|                   |
 |               |               |                   |                   |
 |               |               |                   |--INSERT mov (15->18)|
 |               |               |                   |--UPDATE stock=18->|
 |               |               |                   |--COMMIT---------->|
 |               |               |                   |                   |
 |<-OK           |               |                   |                   |
 |               |<-OK           |                   |                   |
 |               |               |                   |                   |
 | Final stock = 18                                             |
 | mov A: stock_anterior=10, stock_nuevo=15                     |
 | mov B: stock_anterior=15, stock_nuevo=18                     |
```

Note: SQLite serializes writes even in WAL mode. If both transactions attempt to write simultaneously, one may see `SQLITE_BUSY`; the retry middleware handles it. The key guarantee is that each `stock_nuevo` is computed from the most recently committed `stock_actual`.

## 8. Architecture Decision Records (ADRs)

### ADR-001: SQLite over PostgreSQL

**Choice**: SQLite (WAL mode)
**Alternatives considered**: PostgreSQL, MySQL
**Rationale**: Internal tool with 5-10 concurrent users max. SQLite requires zero configuration, no separate process, and single-file backup. WAL mode provides sufficient read concurrency. If concurrent writes become a bottleneck, the schema is designed to migrate cleanly to PostgreSQL via SQLAlchemy or asyncpg.

### ADR-002: SvelteKit over React

**Choice**: SvelteKit PWA
**Alternatives considered**: React + Vite, Next.js
**Rationale**: Smallest production bundle, fastest Time-to-Interactive (TTI), and minimal boilerplate. For a warehouse mobile app where every millisecond matters and network may be spotty, SvelteKit's compiled output is the best fit. Built-in PWA support via `vite-plugin-pwa`.

### ADR-003: html5-qrcode over native BarcodeDetector

**Choice**: html5-qrcode v2.3.8
**Alternatives considered**: Native `BarcodeDetector` API, ZXing-JS, Dynamsoft
**Rationale**: Single library handles both QR codes and 1D barcodes (EAN-13, CODE-128, UPC-A) with one `Html5QrcodeScanner` instance. Native `BarcodeDetector` has limited iOS Safari support and no QR+barcode unification. html5-qrcode provides `formatName` in the callback for automatic sector-vs-product branching.

### ADR-004: CSS Grid over Canvas/SVG for Map

**Choice**: Nested CSS Grid per shelf
**Alternatives considered**: HTML5 Canvas, SVG, tables
**Rationale**: Each shelf has independent variable dimensions (`filas` x `columnas`). CSS Grid allows declarative layout with `repeat()` and `minmax()`, native touch event handling, DOM accessibility, and easy color-coding via CSS classes. Canvas would require manual hit-testing and re-rendering on every state change.

### ADR-005: Session Auth over JWT

**Choice**: Server-side session tokens stored in SQLite
**Alternatives considered**: JWT (stateless), OAuth2
**Rationale**: Auth is for audit tracking only, not security boundaries. Server-side sessions are simpler to invalidate, require no token rotation logic, and fit the single-server deployment. Session ID is attached to every `movimientos` record for traceability.

### ADR-006: Append-only `movimientos` table

**Choice**: `movimientos` records are immutable; no UPDATE or DELETE APIs
**Alternatives considered**: Mutable stock ledger, event sourcing
**Rationale**: Accesaniga needs a trustworthy audit trail. Append-only records with `stock_anterior`/`stock_nuevo` chaining make it impossible to alter history. If a mistake is made, a corrective `ajuste` movement is recorded rather than editing the original. This satisfies compliance without the complexity of full event sourcing.

| Component | Estimated Lines | Risk | Mitigation / PR Slice |

| **Scanner** (`Scanner.svelte` + lifecycle + debounce) | 200-280 | **High** | Split: (a) html5-qrcode wrapper + camera error handling, (b) format branching + debounce, (c) stock input + save flow |

| **Backend API** (all endpoints + schemas + repos) | 400-600 | **Medium** | Slice by capability: auth -> products -> estantes/ubicaciones -> movimientos -> import |
| **Audit Trail** (`AuditTrail.svelte` + CSV export) | 150-200 | Low | Single PR acceptable |
| **Shelf Admin** (`ShelfAdmin.svelte` + soft delete) | 120-180 | Low | Single PR acceptable |

### Ask-on-Risk Gate Triggers

The following conditions MUST pause implementation and ask the user before proceeding:

1. **html5-qrcode v2.3.8 fails to initialize on target iOS devices** (camera permission, OverconstrainedError, or torch/zoom controls missing).
2. **Visual map grid renders incorrectly or cells drop below 48px on any target device** (iPhone SE, warehouse Android tablets).
3. **SQLite contention causes > 5% of stock saves to fail even after 3 retries** on real multi-user warehouse WiFi.
4. **Excel import fails on the real `Productos Sotano.xlsx` file** due to unexpected column names, merged cells, or encoding issues.
5. **Any single PR exceeds 400 changed lines** -- must be split per the chained-pr skill.

## 11. Migration / Rollout

No data migration required (greenfield). Rollback plan: stop deployment, delete `app.db` and WAL files, restart from scratch. First production import is reproducible from the original Excel file.

Schema migrations are managed via a simple versioned SQL script runner executed on FastAPI startup:

```python
# core/migrations.py
MIGRATIONS = [
    (1, "create_tables", "..."),
    (2, "seed_users", "..."),
]
```
